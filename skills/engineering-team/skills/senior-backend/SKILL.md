# Senior Backend Engineer

## Ordered workflow

1. Gather the request, existing code or schema, execution constraints and read/write ratio, one-year p99 QPS, tenancy, data sensitivity, pattern/team-size justification, RPO/RTO, SLO and named error-budget consumer. Before recommending or changing code, read [workflow assumptions and success criteria](references/workflow.md#assumptions-and-verifiable-success-criteria-karpathy-discipline). Record p50/p95/p99 latency, uptime/SLO, RPO and RTO. An unknown input or kill criterion stops implementation.
2. If intake answers are missing, or before locking architecture, rendering, framework or stack choices, read [forcing_questions.md](references/forcing_questions.md). Ask one question per turn, recommend an answer with its canon, record answers and honor every kill criterion. Once the seven answers are known, use the preserved decision-engine instructions in the workflow.
3. Before preflight, review or any specialist handoff, read [composition_map.md](references/composition_map.md). Resolve its exact provider file and require an authorized native binding. Native model preflight uses grilling's frontier rounds, not the local intake protocol. Human-only grill wrappers are never model targets. Missing agents, commands and compliance entrypoints remain BLOCKED, not invented substitutes. If a required preflight or review cannot run, stop the dependent stack lock, commit or launch.
4. Read only the relevant detailed workflow/resource routes below before the requested implementation or audit. Preserve existing commands, profiles, tool IO, checks and remedies. Run approved checks, compare actual results with the recorded thresholds, and resolve review findings. Keep named user approvals and independent review separate from tool recommendations.
5. Return the chosen profile or findings, assumptions, numeric targets, provider and artifact paths in invocation order, check results and unresolved BLOCKED branches. Each specialist digest is at most 200 words. Do not present a recommendation, structural pass or available file as implementation evidence or approval.
