# agent-harness

Turn any domain folder of this repo into a **bounded agentic loop**: pick up a goal,
compile it into tasks with machine-run verification, execute, verify, retry with caps,
escalate to a human when budgets exhaust, and close only when everything is verified.

```
GOAL → goal_compiler → PLAN → loop_controller: [execute → verify]* → CLOSE
                                     ↑ retry ≤ caps, changed approach
                                     └ ESCALATE — never fake success
```

## What ships

| Piece | Purpose |
|---|---|
| `skills/agent-harness/scripts/harness_manifest_builder.py` | Scan a checkout domain to `manifest.v2`; `--check` detects committed drift without writing |
| `skills/agent-harness/scripts/goal_compiler.py` | Goal + manifest to `plan.v2`; vague/no-match/ambiguous/user-only refusals |
| `skills/agent-harness/scripts/loop_controller.py` | `state.v2` `init/next/record/verify/close/status`; controller runs checks itself |
| `skills/agent-harness/scripts/provider_bindings.py` | Shared exact-path YAML identity, invocation and live hash validation |
| `skills/agent-harness/assets/harnesses/*.json` | 18 committed per-domain manifests, regenerated by builder only |
| `skills/agent-harness/assets/harness_manifest.schema.json` | Manifest schema |
| `skills/agent-harness/references/` | Loop canon, verification discipline, domain design, operations and provider bindings |
| `agents/harness-runner.md` | Stateless one-task-per-invocation executor |
| `commands/cs-harness.md` | `/cs:harness <domain> <goal>` end-to-end driver |

Runtime tools require Python 3.10+ and PyYAML, already used by repository CI. The three
CLI tools support `--help` and `--sample`; the shared helper is not a CLI. Examples and
tool smoke/sample passes are not evidence that a user's objective is met.

Run from the actual checkout root, not `skills/`. Read
[runtime operations](skills/agent-harness/references/runtime_operations.md) for commands,
all 18 asset filenames and exit codes. Read
[provider bindings](skills/agent-harness/references/provider_bindings.md) for role
classification, hash scope, legacy refusal and regeneration. State/plan v1 cannot be
resumed as v2; preserve old state and compile/init a new file after review.

## Regression checks

From the checkout root:

```bash
python3 -m unittest discover -s skills/engineering/agent-harness/tests -p 'test_*.py' -v
HARNESS_SOURCE_ROOT="$PWD" python3 -m unittest discover \
  -s skills/engineering/agent-harness/tests -p 'test_*.py' -v
H=skills/engineering/agent-harness/skills/agent-harness
python3 "$H/scripts/harness_manifest_builder.py" --all --repo-root . \
  --out-dir "$H/assets/harnesses" --no-timestamp
python3 "$H/scripts/harness_manifest_builder.py" --check --repo-root .
```

Tests clean temporary fixtures by default. `HARNESS_KEEP_TEST_FIXTURES=1` explicitly
retains them for inspection. `HARNESS_SOURCE_ROOT` adds read-only tests against genuine
installed providers; `HARNESS_TEST_TMPDIR` chooses the fixture directory. The schema
regression checks the vocabulary used by this manifest schema with stdlib assertions;
it is not a general JSON Schema implementation. No additional test dependencies are needed.
Never regenerate committed assets by hand or run against untrusted check commands.
