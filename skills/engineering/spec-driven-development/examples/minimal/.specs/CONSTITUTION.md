# Constitution

## Principles
State observable behavior before implementation. Prefer the smallest design with meaningful failure tests. Test assertions are evidence, not a safety proof.

## Boundaries
Always protect message contents from telemetry. Ask before changing observable behavior or introducing dependencies. Never send data, deploy, or commit automatically.

## Approval policy
A project owner approves each phase in a later turn. Build authorization is a human-authored record tied to a reviewed content snapshot. This demonstration contains no real approval. Stop after one task and ask for verification.
