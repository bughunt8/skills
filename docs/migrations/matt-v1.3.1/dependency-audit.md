## Importer plan without baseline relaxation

Use 27 narrowly scoped source entries with native destination `skills/<bucket>/<name>` and one `support` mapping from the corresponding upstream skill directory to `""`. That preserves every sibling resource without a nested duplicate. Current support mappings produce provenance but do not count top-level skills for collection `mandatory`, so pair this plan with an exact 27-entry release-closure check rather than claiming the existing mandatory mechanism covers it. [Mapping and validation implementation](https://github.com/bughunt8/skills/blob/5f132c008d5c8d261b4fa30e94899151c186ce94/scripts/sync_vendor.py)

Normal sync currently refuses a populated destination without `.vendor-owned.json`, and its replacement code deletes a target before copying the new tree. The parent needs explicit importer archive/adoption handling, with an allowlist and hash verification, before applying these entries. Do not forge ownership files, suppress the refusal, or say the current script already archives old content. [Ownership refusal and replacement](https://github.com/bughunt8/skills/blob/5f132c008d5c8d261b4fa30e94899151c186ce94/scripts/sync_vendor.py)
